# BulkMine

Minecraft 26.1〜26.3 / Fabric 用の一括破壊Modです。土や石を立方範囲でまとめて掘り、木を一括で伐採します。キーひとつで切り替えでき、現在の状態は常に画面に表示されます。

追加アイテムもレシピもありません。既存のツールの挙動を拡張するだけです。

---

# 利用者向け

## 動作環境

| | |
|---|---|
| Minecraft | 26.1 / 26.1.1 / 26.1.2 / 26.2 / 26.3 |
| Mod Loader | Fabric Loader 0.19.3 以上 |
| 必須Mod | Fabric API（遊ぶMinecraftバージョン用のもの） |
| Java | 25 以上（Minecraft 26.x の要件） |

## 導入

`bulkmine-<バージョン>.jar` を `mods` フォルダに入れるだけです。

**マルチプレイではサーバー側にも必須です。** 破壊処理と設定はすべてサーバーが持っているため、クライアントにだけ入れた状態でサーバーに接続すると、HUDが「非対応」と表示され機能は動きません。シングルプレイでは意識する必要はありません。

## 使い方

初期状態ではOFFです。**`V`キー**で切り替えます（キー設定から変更できます）。

押すたびに **ON(3) → ON(5) → OFF** と3段階で切り替わります。サイズを選ぶ操作とON/OFFが1つのキーにまとまっているので、通常はコマンドを使う必要はありません。

段階は `toggleSizes` で変更でき、`[3, 5, 7]` のように増やすことも `[3]` にして単純なON/OFFに戻すこともできます。

画面の隅に現在の状態が常に表示されます。

| 表示 | 意味 |
|---|---|
| `一括ON:3`（緑） | 有効。数字は立方サイズ |
| `一括OFF`（グレー） | 無効 |
| `非対応`（赤） | 接続先のサーバーにBulkMineが入っていない |

切替時はアクションバーにも同じ配色で通知が出ます。

F1（UI非表示）とF3（デバッグ画面）の間は隠れます。

## 破壊される範囲

### 石・土系（立方範囲）

カーソルのブロックを中心とした **N×N×N から、カーソルより下の層をすべて除いた範囲**です。既定のサイズ3なら 3×3×2 の18ブロックになります。

視線の向きでは回転しません。常にワールドの軸に沿うので、平らな床を上から掘れば 3×3×1、垂直な壁を横から掘れば 幅3×高2×奥2 になります。

サイズは**プレイヤーごと**で、再ログイン後も保持されます。通常は `V` キーで選びますが、`toggleSizes` にない7や9を使いたい場合は `/bulkmine config size <奇数>` で直接指定できます。

その状態で `V` を押すと、次の段階には進まず**OFFになります**。7や9は巡回の途中ではないためです。もう一度押すと `toggleSizes` の先頭（既定では3）から始まります。

### 木・巨大キノコ（一括伐採）

木は**種類ごとの組**（原木・葉・根）で定義されていて、伐採は**その木自身のブロックだけ**を巻き込みます。オークを切っても隣のシラカバの葉は残り、暗い森でダークオークを切っても、接している巨大キノコの傘は削れません。

組み込みの組は、オーク（ツツジの葉を含む）、トウヒ、シラカバ、ジャングル、アカシア、ダークオーク、ペールオーク、サクラ、マングローブ、真紅・歪んだ巨大キノコ（ネザーウォートブロック・シュルームライトが傘）、巨大キノコ（赤・茶の傘）です。

どこを叩くかで動作が変わります。

| 叩いたもの | 道具 | 刈られるもの |
|---|---|---|
| 原木・柄 | 斧 | 叩いた高さ以上の同じ木の原木と、その木の葉（全方向） |
| 葉・傘 | その葉に本来の適正ツール（下表）、葉ならハサミも | つながった同じ木の葉。**叩いた高さより下は刈らない**。原木は刈らない |
| マングローブの根 | 斧 | 下記「マングローブの根」参照 |

| 葉の種類 | 適正ツール |
|---|---|
| 普通の葉、ネザーウォートブロック、シュルームライト | クワ（葉はハサミも可） |
| キノコの傘 | 斧 |

剣も葉を速く壊せますが、戦闘中の空振りで樹冠を刈ってしまわないよう対象外です。クワとハサミはツール登録なしで使えます。Paxelはクワの適正も持つので葉にも効きます。

斜め方向を含む26方向をたどり、原木は叩いた位置より下には伸びません（切り株が残ります）。探索範囲は原木から**水平方向に** `treeRadius`（既定16）までで、高さには制限がありません。高さ30前後になる巨大トウヒや巨大ジャングルも根元から倒れます。

木の組に含まれるブロックは立方範囲の対象になりません。石を掘っている隣に木が立っていても、幹が巻き込まれることはありません。

#### マングローブの根

幹を切ると、**根は残ります**。根も含めて片付けたいときは根を叩きます。

根を斧で叩くと、そこから根をたどって幹を探します（`rootDistance`、既定6ブロック以内）。

- **幹が見つかった場合**：その幹を中心に木全体を伐採します。**叩いた根の高さ以上**の原木・葉・根がすべて対象で、それより下の根は残ります。
- **見つからなかった場合**：たどれた範囲の根だけを刈ります。

泥だらけのマングローブの根は土の扱いで、シャベルの立方範囲で掘ります。木の一部としては扱いません。

隣のマングローブと根が接している場合、範囲内にある隣の木の根も一部刈られます（根はどの木のものか判別できないため）。隣の木の幹が倒れることはありません。

#### プレイヤーが設置した葉

設置した葉と自然に生えた葉は区別できます（原木や根、キノコの傘は区別できません）。`distinguishPlacedLeaves`（既定 true）が有効な間は次のように動きます。

- **自然物から始めた場合**（原木・根・自然の葉）：設置した葉は巻き込みません。生け垣や建物の葉の装飾が守られます。
- **設置した葉から始めた場合**：設置した葉も自然の葉も刈ります。

手で組んだ飾りの木を幹から切ると、原木だけ消えて葉が残ります。残った葉はクワで叩けばまとめて刈れます。

`false` にすると区別せず、すべての葉を同じように扱います。

#### 自分で追加した木

他Modの木などは `/bulkmine block add <ブロック> log` / `leaves` で追加できます。追加したものはすべて**1つの組（カスタム組）**として扱われ、カスタム組の中では種類を問わずまとめて伐採しますが、組み込みの木を巻き込むことはありません。

組み込みの木に含まれるブロックはコマンドでは追加できません。組み込みの木や新しい組は、設定ファイルの `trees` を直接編集してください。

#### 既知の制限

真紅・歪んだ巨大キノコは、根元近くの低い位置に、柄にも傘にもつながっていないネザーウォートブロックの破片を生成することがあります。つながりをたどる仕組みでは届かないため、数個残ることがあります。

## 対象になるツール

バニラのつるはし・斧・シャベルは常に認識されます。

**他のModのツールは自動では登録されません。** 手に持って以下を実行してください。

```
/bulkmine tool add hand all
```

たとえば The True Paxels のPaxelは7種類あるので、それぞれ手に持って1回ずつ実行します。ロールを分けたい場合は `all` の代わりに `pickaxe|shovel` のように指定できます。

Paxelのように複数ロールを持つツールは、カテゴリをまたいで採掘します。石と土が混在していても1回の破壊でまとめて掘れます。

## 対象にならないブロック

**ドロップが得られないブロックはスキップされます。** 石のつるはしでダイヤ鉱石を掘っても、カーソルのブロックはゲーム本体が壊しますが、周囲の鉱石は残ります。無駄に消し飛ばさないための仕様です（`requireCorrectTool` で無効化できます）。

対象ブロックは設定ファイルにすべて明示されており、行を消すだけで除外できます。ブラックリストに入れたブロックは、ホワイトリストに含まれていてもスキップされます。

## ツールの耐久

耐久が2以上残っているツールは**残り1で止まり、壊れません**。それ以降は耐久を消費せずに範囲破壊を続けます。この状態になると「耐久値が限界です！」と赤字でアクションバーに警告が出て、同時に効果音が鳴ります（限界で止まったスイングごとに毎回）。

**耐久1のツールで掘った場合、この警告は出ません。** 警告は「止めたのでツールは残ります」という意味なので、そのスイングで壊れるツールには出しません。効果音は本人にだけ聞こえ、`durabilityWarningSound` で好きなサウンドIDに変更できます。空文字にすれば無音になります。

耐久1のツールで掘った場合はツールが壊れますが、**その場合も範囲破壊は最後まで実行されます**。

### 消費速度の変更

`durabilityChance`（%、既定100）で消費量を調整できます。耐久力エンチャントと同じく**1ブロックごとに確率判定**する方式です。100なら毎ブロック消費、50なら平均して半分、0なら消費なし。`33.3` のような小数も指定できます。

適用されるのは**一括破壊で追加された分だけ**です。カーソル位置のブロックはゲーム本体が消費するため、この設定に関わらず常に1消費します。トグルOFF時や、対象外ブロック・適正ツール外で一括が発動しなかった場合も、バニラ通り毎回消費します。

耐久力エンチャントは本設定に**上乗せで適用**されます。50%＋耐久力IIIならかなり長持ちします。

なお、消費量は固定1ではなくツールごとの `damagePerBlock`（バニラのツールは全て1）に従い、硬度0のブロックはバニラ同様に消費しません。

## コマンド

### 全プレイヤーが使えるもの

| コマンド | 内容 |
|---|---|
| `/bulkmine config` | 自分の設定とサーバー設定を表示 |
| `/bulkmine config size <1-15>` | 自分の立方サイズを変更（奇数のみ） |

ON/OFFの切替コマンドはありません。`V` キーがサイズ選択も兼ねており、コマンド版が下位互換になるためです。

シングルプレイではチート無効のままでも使えます。

### 管理用

シングルプレイでは常に、サーバーでは権限レベル2以上で使えます。

| コマンド | 内容 |
|---|---|
| `/bulkmine tool add <アイテム\|hand> <ロール>` | ツールを登録 |
| `/bulkmine tool remove <アイテム\|hand> [ロール]` | ツール登録を解除 |
| `/bulkmine tool list` | 登録済みツール一覧 |
| `/bulkmine block add <ブロック\|hand> <種類>` | 対象ブロックを追加 |
| `/bulkmine block remove <ブロック\|hand>` | 対象ブロックから除外 |
| `/bulkmine block deny <ブロック\|hand>` | ブラックリストに追加 |
| `/bulkmine block allow <ブロック\|hand>` | ブラックリストから解除 |
| `/bulkmine block list` | 各一覧の件数とブラックリストを表示 |
| `/bulkmine reload` | 設定ファイルを再読込 |

ツールのロールは `pickaxe` / `axe` / `shovel` / `all` で、`|` または `,` で連結できます（例: `pickaxe|shovel`）。

ブロックの種類は `pickaxe` / `shovel`（立方範囲）と `log` / `leaves`（カスタム組の原木・葉）です。`pickaxe|shovel` は連結できますが、`log` と `leaves` は単独で指定します。以前の `axe` は `log` として受け付けます。組み込みの木に含まれるブロックは追加・除外できないので、設定ファイルで編集するか `deny` で除外してください。

コマンドで変更した内容は設定ファイルへ即座に書き戻されます。

## 設定ファイル

`config/bulkmine.json` に初回起動時、既定値の入ったファイルが生成されます。ファイル内のコメント行でサーバー設定とクライアント設定が明示的に分かれています。

サーバー設定はマルチプレイでは接続先サーバーの値が使われ、手元の値は無視されます。クライアント設定（HUDの表示位置）はその逆で、常に自分の設定が使われます。

| 主な項目 | 既定 | 内容 |
|---|---|---|
| `defaultCubeSize` | 3 | サイズ未選択のプレイヤーの初期値 |
| `maxCubeSize` | 9 | プレイヤーが設定できる上限 |
| `toggleSizes` | `[3, 5]` | `V` キーが巡回するサイズ（末尾の次がOFF） |
| `breakLeaves` / `leafDistance` | true / 6 | 伐採時に葉も刈るか / 葉をたどる距離 |
| `distinguishPlacedLeaves` | true | 設置した葉と自然の葉を区別する |
| `rootDistance` | 6 | 叩いた根からたどる距離 |
| `maxLogs` / `maxLeaves` / `maxRoots` | 256 / 1024 / 256 | 一度に刈る上限 |
| `treeRadius` | 16 | 伐採範囲（水平方向のみ） |
| `aggregateDrops` | true | ドロップを起点ブロックに集約 |
| `allowWhileSneaking` | true | スニーク中も動作 |
| `requireCorrectTool` | true | 適正ツールでないブロックをスキップ |
| `durabilityChance` | 100.0 | 追加1ブロックあたりの耐久消費確率（%） |
| `durabilityWarningSound` | `minecraft:block.anvil.place` | 耐久限界時の効果音（空文字で無音） |
| `tools` | 空 | 追加登録したツール |
| `blocks.pickaxe` / `shovel` | 各一覧 | 立方範囲の対象ブロック |
| `blocks.trees` | 12種 | 木の組（設定ファイルでのみ編集） |
| `blocks.customTree` | 空 | コマンドで追加した木（1つの組） |
| `blocks.blacklist` | 空 | 常にスキップ（最優先） |
| `client.hudCorner` | `BOTTOM_RIGHT` | HUDの表示位置（四隅） |

ブロックの指定は `minecraft:stone` のようなIDのほか、`#c:ores` のようなタグ参照も書けます。

設定ファイルは読み込み時にテンプレート経由で書き戻されます。古い形式のファイルは自動で移行し、値は保持されます。**手書きで追加したコメントは失われます。**

1.1以前の `fellable` / `leaves` は、組み込みの木に含まれるものは吸収され、それ以外（手で追加したもの）はカスタム組に移ります。

## 配布プロファイルに同梱する場合

設定ファイルは引き継がれないため、`config/bulkmine.json` も一緒に配布しないと、受け取った側は**ツールが1つも登録されていない状態**から始まります。CurseForgeのプロファイルをエクスポートする場合は、overridesに設定ファイルも含めてください。

# 開発者向け

## 環境

JDK 25 が必要です（Minecraft 26.2 の要件）。

`gradle.properties` の `org.gradle.java.home` に **JDK 25 の絶対パスがハードコードされています**。別のマシンで作業する場合は書き換えるか、PATHが通っているなら行ごと削除してください。

同ファイルの `org.gradle.jvmargs` にある `-Duser.language=en` は、javacのエラーメッセージが日本語ロケールで文字化けするのを避けるためのものです。

## ビルド

```
build.bat
```

ゲームテストを実行し、通ったら `dist\bulkmine-<バージョン>.jar` を生成します。テストが落ちた場合 `dist\` は更新しません。バージョンは `gradle.properties` の `mod_version` から読み取ります。

テストを飛ばす場合は `build.bat --no-tests` です。

個別のGradleタスク:

| タスク | 内容 |
|---|---|
| `gradlew runClient` | 開発用クライアント起動 |
| `gradlew runGametest` | ゲームテスト（サーバー起動〜自動実行） |
| `gradlew build` | jarのビルドのみ |

`run/` は開発用クライアントのゲームフォルダです。ワールド、ログ、Modが書き出す設定、テスト用に入れた他のModがすべてここに入るため、リポジトリからは除外しています。

## ソース構成

Loomの `splitEnvironmentSourceSets()` により、サーバー／クライアントの分離がコンパイル時に強制されます。

| ディレクトリ | 内容 |
|---|---|
| `src/main` | サーバー・共通。破壊処理、設定、コマンド、永続化。`src/client` を参照できない |
| `src/client` | クライアント専用。HUD、キーバインド、受信したステートの保持 |
| `src/gametest` | ゲームテスト。**別Mod（`bulkmine-gametest`）として構成** |

ゲームテストを別Modに分けているのは、`fabric-gametest` エントリポイントを製品版の `fabric.mod.json` に書いてしまうと、テストクラスを含まない配布jarでは `ClassNotFoundException` で起動不能になるためです。

クライアントは状態を自分で決めません。トグルキーはサーバーへ要求を送るだけで、表示するのはサーバーから配信された値です。

## テスト

```
gradlew runGametest
```

64件のゲームテストが、実際の破壊経路 `ServerPlayerGameMode.destroyBlock` を通して形状・ホワイトリスト・ロール・伐採・耐久・ドロップ位置を検証します。結果は `build/junit.xml` に出ます。

木のテスト（`TreeGameTests`）の後半は、**本体のワールド生成で本物の木を生やして**から伐採します。巨大トウヒの高さやマングローブの根は手で積んだ柱では再現できないためです。テストの格子から離れた座標（x=20000付近）に生成し、テストワールドは実行間で保存されるため毎回その範囲を消去してから生やします。土台の下に石を敷いているのは、マングローブの根が泥を突き抜けて伸び続け、最大長を超えて生成に失敗するのを防ぐためです。

### 対応バージョンの確認方法

ビルドは 26.2 に対して行い、同じ jar を 26.1〜26.3 で使います。対応範囲を確認するときは、作業コピーで `minecraft_version` と `fabric_api_version` だけを差し替え、**26.2 でコンパイルした `build/classes/java/main` と `client` をそのまま置いて** `gradlew runGametest -x compileJava -x compileClientJava` を実行します。ソースを各バージョン向けにコンパイルし直すと、配布する jar そのものの互換性を確かめたことにならないためです（26.x は難読化されていないので、クラスは再マップなしでそのまま読み込まれます）。

26.3 では `ConfiguredFeature` が `Feature` に統合され、`Registries.CONFIGURED_FEATURE` も `Registries.FEATURE` になりました。Mod 本体は使っていませんが、`TreeGameTests` の木を生やす部分がこれを使っているため、26.3 で試すときはそれらを書き換えます。

Fabricのモックプレイヤーは `gameMode()` がCREATIVE固定です。そのままではドロップも耐久消費も発生しないため、テスト側で `abilities.instabuild` を落としています。製品コード側も `isCreative()` ではなく、バニラ自身が使う `preventsBlockDrops()` を見ています。

## 生成物の再生成

`src/main/resources/default-config.json` は手書きせず、`ConfigWriter` から生成します。ゲームテストが両者の一致を検証しているので、`ConfigWriter` を変更したら必ず再生成してください。

```
javac -d build/tmp/gen src/main/java/io/github/tsiw/bulkmine/config/BulkMineConfig.java src/main/java/io/github/tsiw/bulkmine/config/BlockDefaults.java src/main/java/io/github/tsiw/bulkmine/config/ConfigWriter.java tools/DumpDefaultConfig.java
java -cp build/tmp/gen io.github.tsiw.bulkmine.config.DumpDefaultConfig
```

アイコンも同様に生成物です。

```
java tools/GenIcon.java
```

## 実装上の注意点

過去に実際に踏んだ問題です。いずれも症状が出るまで時間がかかる種類のものなので、該当箇所を触る際は注意してください。

**設定のID解決はサーバー起動時まで遅らせる。** `ToolRegistry` / `BlockWhitelist` の解決を `onInitialize()` で行うと他Modのアイテム登録と競合し、登録済みのツールが起動のたびに黙って捨てられます。`ServerLifecycleEvents.SERVER_STARTING` で行っています。

**アタッチメント型はMod初期化で明示的に登録する。** 登録はstatic初期化子にありますが、参照がラムダの中だけだとクラスが初めて触られるのが「最初のプレイヤー参加時」になり、プレイヤーデータ読込に間に合いません。保存済みの設定が毎回破棄されます。`PlayerSettings.init()` の呼び出しがそのためだけに存在します。

**耐久はAFTERイベントの発火順に注意。** FabricのAFTERイベントは、バニラが起点ブロック分の耐久を消費する**前**に発火します。残り1まで削るとその後バニラが最後の1を取ってツールが壊れます。BEFOREで取ったスナップショットと比較して、未消費なら2を残しています。

この「床」は消費の可否と警告表示の両方に効きますが、意味が違います。消費を拒否する理由は「限界で止めた」と「そもそも足りない」の2通りあり、後者では直後にツールが壊れるため警告を出すと嘘になります。`toolSurvivesTheSwing` がこれを分けており、**スイープ開始前に評価する必要があります** — 消費が始まると `durabilityFloor` の比較対象が崩れ、床が1に見えてしまうためです。

**起点ブロックの耐久には手を出さない。** 上記の理由で、起点分の消費を事前に止める手段がありません。後から返す実装も試しましたが、ツールが壊れた場合だけは戻せず挙動が揃わないため、起点はバニラに任せる方針に統一しました。`durabilityChance` は追加ブロックのみに掛かります。

**木の探索半径は水平方向のみ。** 以前は縦横共通の距離で16に制限しており、高さ30前後の巨大トウヒ・巨大ジャングルの上半分が残っていました。高さは `maxLogs` で既に抑えられています。テストでは、高さも距離に含める実装に戻すと巨大な木のテストだけが落ち、高さ13が上限の背の高いシラカバは通ることを確認しています。

**設定ファイルのテンプレートは名前付きの差し込み。** 位置指定（`%1$s`〜）だった頃は、項目を足すたびに後続の番号をすべてずらす必要がありました。`ConfigWriter.fill` は差し込み漏れ・余りがあれば例外にします。

**ユーザーが読むファイルはASCIIのみ。** 設定ファイルとログ出力は英語です。ゲーム外のコンソールやエディタがUTF-8とは限らず、手編集する設定ファイルが文字化けするのは英語表記より悪いためです。日本語は `lang/ja_jp.json` にのみ存在します（MinecraftがUTF-8として読むことが仕様で保証されている唯一の場所）。
